# Problem Number - 535B Tavas and SaDDas

**Problem Link:** [https://codeforces.com/problemset/problem/535/B](https://codeforces.com/problemset/problem/535/B)

## Topics
- Bitmasks
- Combinatorics
- Implementation

## Constraints
- n is a lucky number consisting of digits 4 and 7 only.
- $1 \le n \le 10^9$
- Time limit per test: 1 second
- Memory limit per test: 256 megabytes

## Intuition / Approach
- Lucky numbers are numbers containing only the digits 4 and 7. The problem asks us to find the 1-based index of a given lucky number $n$ if all lucky numbers are sorted in ascending order.
- Lucky numbers can be thought of as being generated by length. There are $2^1$ lucky numbers of length 1, $2^2$ of length 2, and in general, $2^k$ lucky numbers of length $k$.
- The total number of lucky numbers strictly shorter than the length of $n$ (let's call it $L$) is given by $2^1 + 2^2 + \dots + 2^{L-1} = 2^L - 2$. This forms our base count.
- To account for numbers of the same length $L$, we can treat '4' as binary `0` and '7' as binary `1`. This transforms the lucky number's suffix/digits into a binary representation offset.
- Iterating through the string from right to left, whenever we encounter a '7', we add the corresponding binary weight $2^{L - i - 1}$ to our offset counter $c$.
- The final answer is the sum of the base count of shorter numbers, the offset for numbers of the same length, and 1 for the number itself: `count + c + 1`.

## Time and Space Complexity
- **Time Complexity:** $O(L)$, where $L$ is the length of the string representation of $n$, making it virtually instantaneous.
- **Space Complexity:** $O(L)$ to store the input string, or $O(1)$ auxiliary space.
